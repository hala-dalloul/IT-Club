# UCAS IT CLUB

موقع نادي تكنولوجيا المعلومات ولعبة اكتشاف المسار. يحافظ المشروع على تصميم اللعبة وألوانها وأوزان الأسئلة، ويضيف صفحات النادي العربية والإنجليزية وإدارة المحتوى باستخدام Firebase.

## المسارات

- `/`: لعبة اكتشاف المسار الأصلية باللغة العربية.
- `/club`: الصفحة الرئيسية للنادي.
- `/club/about`: الرؤية والرسالة والأهداف والمجالات.
- `/club/projects` و`/club/projects/:id`: معرض المشاريع والبحث والفلترة والتفاصيل.
- `/club/members` و`/club/members/:id`: المؤسسون واللجان وصفحات الأعضاء ومشاريعهم.
- `/club/events` و`/club/events/:id`: الأخبار والفعاليات القادمة والسابقة.
- `/club/achievements`: الخط الزمني للإنجازات.
- `/club/partners`: الشراكات.
- `/club/join` و`/club/contact`: نماذج الانضمام والتواصل.
- `/club/admin`: لوحة الإدارة؛ `/admin` يعيد التوجيه إليها.

فصل الموقع تحت `/club` يحافظ على رابط اللعبة وتجربتها الحالية. صفحات الموقع الجديدة ثنائية اللغة، أما اللعبة فتبقى بالعربية كما كانت.

## التشغيل والتحقق

المشروع يستخدم Node.js حديثًا وBun ويحافظ على `bun.lock`.

```sh
bun install --frozen-lockfile
bun run dev
bun run typecheck
bun run build
bun run test:rules
```

اختبارات القواعد تستخدم مشروعًا تجريبيًا باسم `demo-ucas-it-club` ومحاكيَي Firestore وStorage، ولا تتصل ببيانات الإنتاج. يلزم Java 17 أو إصدار متوافق مع نسخة Firebase CLI المثبتة. يتم تنزيل ملفات المحاكي في أول تشغيل.

## تفعيل Firebase

1. أنشئ مشروع Firebase باسم النادي، ثم سجل تطبيق Web.
2. انسخ `.env.example` إلى `.env.local` واملأ إعدادات تطبيق Web الخمسة. لا تضع Service Account أو مفتاحًا خاصًا في أي متغير `VITE_*`، إذ تظهر هذه المتغيرات في المتصفح.
3. فعّل Email/Password في Authentication، وأنشئ Firestore وStorage، وأضف نطاق الموقع إلى Authorized domains في Authentication.
4. أنشئ حساب المدير الأول من Firebase Console. أنشئ وثيقة `admins/{UID}` بالقيم `uid`, `name`, `email`, `role: "super_admin"` باستخدام إدارة Firebase الموثوقة. لا يوجد مستخدم مدير افتراضي أو كلمة مرور مضمّنة في الكود.
5. انشر القواعد قبل تفعيل النماذج:

```sh
bunx firebase login
bunx firebase deploy --only firestore:rules,storage --project YOUR_PROJECT_ID
```

6. افتح `/club/admin` وسجّل الدخول. أدخل النصوص الرسمية في إعدادات الموقع، ثم الأعضاء والمشاريع والفعاليات والشراكات والإنجازات.
7. لإنشاء محرر، أنشئ حسابه في Firebase Authentication ثم أضف UID والاسم والبريد في تبويب المحررين. إزالة السجل من اللوحة تلغي صلاحيات المحتوى فورًا، ولا تحذف حساب Authentication نفسه. حساب المدير العام لا يستطيع حذف نفسه من الواجهة.

بدون إعدادات Firebase تعرض الصفحات أقسامًا فارغة وتتعطل أزرار إرسال النماذج ولوحة الإدارة بوضوح. لا يوجد حفظ محلي وهمي أو رسالة نجاح دون استجابة Firestore. لم تُملأ أسماء أعضاء أو إنجازات أو شركاء افتراضيين.

**التخزين والفوترة:** وثيقة SRS تفترض Spark. توضح [وثائق Firebase الحالية](https://firebase.google.com/docs/storage/faqs-storage-changes-announced-sept-2024) أن Cloud Storage يتطلب Blaze ابتداءً من 3 فبراير 2026. لم يتم تفعيل فوترة أو إنشاء موارد سحابية من هذا المشروع. يحدد مالك النادي المشروع والخطة المناسبة قبل النشر.

## البناء والنشر

`bun run build` يحافظ على بناء Lovable/TanStack Start الأصلي. لبناء نسخة ثابتة لـFirebase Hosting دون خادم مخصص:

```sh
bun run build:firebase
bunx firebase deploy --only hosting --project YOUR_PROJECT_ID
```

يرفع Hosting المجلد `dist/client` فقط. تضبط `firebase.json` إعادة التوجيه إلى `/_shell.html` لتعمل روابط الصفحات المباشرة. لا ترفع `dist/server` أو ملفات `.env`.

لم يُنفّذ نشر Firebase بعد؛ يلزم حساب النادي وإعداداته. الرفع إلى GitHub هو حفظ للكود ولا يفعّل Firebase تلقائيًا.

## البريد والمحتوى الرسمي

إشعارات البريد لم تُفعّل. يلزم تحديد بريد اللجنة واعتماد مزوّد البريد ونطاق البيانات المسموح إرسالها إليه. نماذج Firestore ولوحة الطلبات مستقلتان عن البريد. يُقترح أن يحتوي إشعار اللجنة على رقم الطلب ورابط الإدارة فقط؛ لا تُرسل بيانات الطالب قبل موافقة مالك المشروع.

الرؤية والرسالة والأهداف المعتمدة وروابط التواصل والصور وبيانات الأعضاء والمشاريع لم تُقدّم. تُضاف من لوحة الإدارة بعد تفعيل Firebase.

## بنية الكود

- `src/lib/game-data.ts` و`src/lib/scoring.ts`: محتوى اللعبة وأوزانها الأصلية.
- `src/components/game`: واجهات اللعبة، مع الشعار المرفق الجديد بنسبه الأصلية.
- `src/lib/club/model.ts`: نموذج المحتوى والتحقق من النماذج والروابط.
- `src/lib/club/firebase.ts`: عمليات القراءة والكتابة ورفع الصور.
- `src/components/club`: صفحات النادي ومزوّد اللغة والبيانات ولوحة الإدارة.
- `firestore.rules` و`storage.rules`: الصلاحيات والتحقق من البيانات.
- `tests`: اختبارات رفض الوصول والكتابة غير المصرح بها.
- [حالة المتطلبات](docs/srs-implementation.md): المنفّذ وما يحتاج تفعيلًا.
- [الوصف الأصلي للعبة](docs/pathfinder-original-brief.md): مرجع محفوظ دون حذف.

## نموذج البيانات

يحافظ التنفيذ على أسماء المجموعات الواردة في SRS. لتوحيد محرر المحتوى، تستخدم جميع مجموعات المحتوى حقول `title/title_en`, `description/description_en`, `images`. تقابل `members.name/bio/photoUrl` و`partners.name/logoUrl` في الوثيقة هذه الحقول الموحدة. روابط GitHub/Demo/APK مسطحة باسم `githubUrl/demoUrl/apkUrl`. العلاقة الأساسية هي `projects.memberIds` وتستخرج صفحة العضو مشاريعه منها دون نسخ مصفوفة ثانية قد تفقد التزامن. التواريخ العامة بصيغة ISO `YYYY-MM-DD`، وتواريخ التدقيق والطلبات تستخدم Firestore serverTimestamp.

كل عنصر محتوى منشور فور حفظه. لا توجد مسودات في هذا الإصدار. البيانات الخاصة بالطلبات والرسائل لا تُقرأ إلا لحساب إداري. قواعد المحتوى تشترط تسجيل آخر تعديل ومعرّف المحرر. رفع الصور يقبل JPG/PNG/WebP بحد 5 MB ويضغطها مع الحفاظ على النسب قبل التخزين.
