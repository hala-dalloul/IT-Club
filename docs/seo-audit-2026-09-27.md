# SEO audit and improvements — 2026-09-27

## What was checked

Reviewed the route loaders/heads, SEO helpers, server responses, sitemap function, public content model, article rendering, build configuration, and deployment notes. Fetched the deployed homepage, robots.txt, sitemap, one English news article, and a nonexistent URL from `https://ucas.itclub-143.workers.dev`. Inspected local English/Arabic article pages and the admin route in a real browser.

This is a technical/content audit, not a Search Console indexing report or a Core Web Vitals measurement. No production deployment or account changes were made.

## Existing foundations verified

- The deployed homepage returns HTTP 200 with server-rendered titles, description, canonical, Arabic/English/x-default alternates, Open Graph metadata, and JSON-LD.
- The live sitemap contains 26 localized URLs, including news and events. Individual members and admin URLs are excluded.
- The sampled nonexistent URL returns HTTP 404.
- Article pages have readable slugs, individual metadata, article/breadcrumb JSON-LD, and localized content.
- The source already redirects legacy `/club` paths and ID URLs, normalizes trailing slashes, and supports a canonical domain through `VITE_SITE_URL`.
- Localized HTML language/direction, descriptive image alt text, image dimensions, and self-hosted fonts are already present.

## Findings addressed in code

| Finding | Change | Basis |
| --- | --- | --- |
| Admin URLs were disallowed in robots.txt even though the pages carry noindex. Crawlers could not read that directive. | Allow crawling and retain admin/member noindex. Authentication and RLS continue to govern data access. | [Google noindex guidance](https://developers.google.com/search/docs/crawling-indexing/block-indexing) |
| Any item with a date became an Open Graph article, including events. | Limit article type/publication/modified metadata to news. | Match metadata to the page's actual content type. |
| News JSON-LD used a generic club social image when the article had no image. | Include only real, safe article image URLs; omit image when none exists. | [Google Article image guidance](https://developers.google.com/search/docs/appearance/structured-data/article) |
| Headlines were cut at 110 characters; author identification relied on an ID in a separate JSON-LD block. | Preserve the full headline and supply explicit organization author type/name/about URL; show a matching visible byline. | [Google Article guidance](https://developers.google.com/search/docs/appearance/structured-data/article) |
| Breadcrumb markup had no corresponding visible navigation trail. | Add accessible Arabic/English breadcrumbs with crawlable home and section links. | [Google breadcrumb guidance](https://developers.google.com/search/docs/appearance/structured-data/breadcrumb) |
| Search image previews were left at default size. | Add `max-image-preview:large` to indexable pages; retain noindex on excluded pages. | [Google robots directives](https://developers.google.com/search/docs/crawling-indexing/robots-meta-tag) |
| The same WebSite entity used `/` or `/en` as its URL depending on the current page. | Give it one domain-root URL while preserving localized names and page canonicals. | [Google site names](https://developers.google.com/search/docs/appearance/site-names) |
| Search ownership verification required a source edit or file upload. | Add optional build-time Google/Bing meta tokens, with no tag when unset. | [Google ownership verification](https://support.google.com/webmasters/answer/9008080) |
| Site-side sitemap forwarding could throw or stall while reading the origin body. | Bound the full fetch/body read to ten seconds and return uncached 502 on failures. | Keep failed origin reads from producing a cached successful sitemap response. |

Added social image alternative text and normalized long custom descriptions. Existing reciprocal hreflang annotations were retained; they follow [Google's localized-page guidance](https://developers.google.com/search/docs/specialty/international/localized-versions).

The earlier backend changes in this working tree also paginate the sitemap Edge Function. They must be deployed separately from the website; changing local function source does not update the deployed function.

## Remaining work requiring content or account access

1. **Search Console / Bing status is unknown.** No verification meta tag was present in the sampled live homepage, but verification may already exist through DNS, HTML files, or another method. Check the club's account before creating a duplicate property. If needed, choose a URL-prefix property and HTML-tag verification, set `VITE_GOOGLE_SITE_VERIFICATION` to the token's `content` value, rebuild/deploy, then verify and submit `/sitemap.xml`. `VITE_BING_SITE_VERIFICATION` provides the equivalent optional tag for Bing. These values are public ownership tokens, not API secrets; only use tokens from the authorized club account.
2. **Inspect actual indexing after deployment.** Use URL Inspection for both homepages and representative news/event URLs. Check selected canonical, crawl status, Page Indexing, rich-result reports, and Core Web Vitals. Validate representative news pages in Google's Rich Results Test. This audit did not run those account-specific checks or claim rich-result eligibility.
3. **Add real article photography where appropriate.** The sampled board announcement has no article image. Generic logos should not be substituted as article imagery. Upload relevant high-resolution images and maintain meaningful bilingual titles, descriptions, and publication dates.
4. **Event schema requires a content-model change.** The current model has a date but no structured venue/address or event time/timezone. Collect accurate event details, display them on the page, then add eligible Event markup. Do not assume every event takes place at the college. See [Google Event requirements](https://developers.google.com/search/docs/appearance/structured-data/event).
5. **Keep Arabic and English content complete.** Some fields fall back to Arabic when the English field is empty. Review translations when publishing; a language URL alone does not translate the content.
6. **Use the SSR deployment for the public site.** The alternate static build rewrites paths to an application shell and does not provide the same server-rendered SEO guarantees. Preserve the current SSR server entry and its robots/sitemap handlers.
7. **Canonical domain remains the workers.dev address.** If the college subdomain is activated, set `VITE_SITE_URL` in the actual build environment and follow `docs/college-subdomain.md`; verify redirects, canonicals, sitemap, and the new Search Console property together. This audit did not change the domain.
8. **Performance remains a separate measured task.** The build still has a large initial client chunk. No new dependency was added here. Measure field data and mobile performance before claiming ranking or speed improvements.
