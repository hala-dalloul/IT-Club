# حالة تنفيذ متطلبات النادي

اعتُمد Supabase بدل Firebase بناءً على توجيه المستخدم للحفاظ على خطة مجانية. تبقى المتطلبات الوظيفية والهوية البصرية نفسها؛ مصدر SRS وصف للمتطلبات ولا يمنح بحد ذاته صلاحية شراء خدمات أو إرسال بيانات إلى جهات خارجية.

## تفاصيل التنفيذ

ملف `supabase/migrations/202609090001_club.sql` ينشئ مخطط النادي دون حذف بيانات موجودة، ويعمل مرة واحدة داخل معاملة. ملف `supabase/bootstrap-admin.sql` يربط بريد المدير بحساب موجود في Authentication. لا يحتوي أي منهما كلمات مرور أو مفاتيح خاصة.

استُبدلت مجموعات Firestore بجدول محتوى مميّز بحقل `kind`، وجدول طلبات مميّز بحقل النوع، مع تحقق من البيانات والصلاحيات. حقول العرض الحالية بقيت متوافقة مع الواجهة. استُبدلت اختبارات Firebase بمحاكاة PostgreSQL حقيقية محليًا باستخدام PGlite، مع مخططات محلية مصغّرة لـAuth وStorage؛ لا يُعتبر ذلك اختبارًا كاملًا لخدمات Supabase المُدارة.

ترفض قاعدة البيانات حذف صورة مستخدمة حتى عند تجاوز الواجهة. تبدأ إزالة صورة غير مستخدمة بتعليمها للحذف؛ يمنع هذا ربطها بمحتوى جديد بين حذف الملف وحذف سجل المكتبة. تحديث المحتوى والروابط يتم في معاملة واحدة بواسطة trigger.

لا تزال الرؤية والرسالة والأسماء والمشاريع والشراكات بحاجة إلى إدخال معتمد من النادي، ولا تُعرض بيانات تجريبية على أنها إنجازات حقيقية. نتيجة اللعبة استرشادية واللعبة باقية باللغة العربية كما كانت.
